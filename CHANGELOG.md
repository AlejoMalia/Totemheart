# Totemheart

## 0.1.4

### Patch Changes

- Added 6 official plugin packages under `packages/`, each real, independently tested, and duck-typed against the core's already-documented extension points (no core changes required to build any of them): `@totemheart/provider-openai` (real OpenAI-compatible `LanguageProvider`, same throw-on-failure resilience contract as `OllamaProvider`), `@totemheart/store-sqlite` (real, on-disk `EpisodicMemory` adapter via Node's built-in `node:sqlite`, zero dependency — with an honestly documented, explicitly-tested limitation: `EpisodicMemory`'s adapter contract as implemented in core today only routes `store()`/`recall()` through the adapter, not `markResolved()`/wound-tracking/Zeigarnik/REM-salience), `@totemheart/bridge-tts` (real `ExpressionDirectives` prosody output mapped to standard W3C SSML, usable with Azure/Polly/Google TTS), `@totemheart/bridge-robotics` (real posture/action-tendency output mapped to a generic actuator schema, sent over real HTTP to a real listener in tests), `@totemheart/devtools` (a zero-dependency local HTTP dashboard exposing live `getEmotionalState()`/decision-log data), and `@totemheart/audit-kit` (the real cross-mechanism test helpers from `test/integration/cross-mechanism-friction.test.js`, extracted for reuse).
- Added 36 new tests: 34 across the 6 plugins (unit + per-plugin cross-tests against real core modules) plus 2 in `test/plugins-cross/all-plugins-integration.test.js` exercising all 6 plugins wired together into the same real `Totemheart` instance at once (SqliteStore persistence + OpenAIProvider fallback + a live DevServer + TTSBridge + RoboticsBridge + audit-kit's own stress driver, all observed to stay consistent with each other through a real rupture-and-grief scenario). `npm run test:all` runs core (2366) plus plugins (36) = 2402 total; `npm test` alone is unchanged and still only runs core.
- Root `package.json` gained an npm workspaces `packages/*` entry and `test:plugins`/`test:all` scripts; no change to the core package's own zero-dependency footprint or public API.

## 0.1.3

### Patch Changes

- Added 18 new mechanisms modeling human relational friction — the axes a general-purpose emotional architecture tends to under-cover: grief (`GriefEngine`, real power-law decay with Poisson intrusion waves), shame vs. guilt as genuinely separate accumulators (`ShameGuiltSplit`), a transactional apology/acceptance/trust-rebound protocol (`RepairProtocol`), a real self/other/rival threat model (`JealousyTriangle`), a subjective (not wall-clock) time multiplier (`SubjectiveTimeEngine`), affective forecasting with a real forecast-error correction into `DopaminergicEngine` (`AnticipatoryAffect`), bittersweet nostalgic reconsolidation (`NostalgiaEngine`), a real Miller (1944) approach-avoidance gradient conflict (`MotivationalConflict`), self-binding promises with escalating violation cost (`CommitmentDevice`), a budgeted self-regulation resource (`EgoDepletionBudget`, with an explicit replication-crisis caveat on the underlying theory), a real predictive-processing interoceptive-error signal (`InteroceptivePredictionError`), the real two-process model of sleep pressure (`SleepPressure`), the social/physical pain pathway overlap (`PainSocialOverlap`), permanent core-belief scarring distinct from ordinary dissonance (`MoralInjury`), identity-specific threat detection (`IdentityThreatMonitor`), a dynamic Schwartz (1992) value-conflict model (`ValueHierarchy`), the real opponent-process a/b dynamic (`OpponentProcess`), and Social Baseline Theory's real cortisol-decay coupling to attachment trust (`SocialBaselineTheory`). Also added state-dependent attachment-style switching under acute stress to `Attachment.js` and allostatic-load-driven anhedonia to `DopaminergicEngine.js`.
- Wired all 18 into the real `Totemheart.js` pipeline (not left standalone) — see `README.md`'s architecture tables and `CALIBRATION.md` for the full citation ledger — and extended `toJSON()`/`restoreState()` with 10 new real persisted fields.
- Grew the test suite from 2298 to 2366 real, deterministic tests: `test/integration/human-friction-mechanisms.test.js` (60 directed per-mechanism tests) plus `test/integration/cross-mechanism-friction.test.js` (8 deliberate cross-mechanism scenarios — not one mechanism at a time, but several of the 18 new ones stacked together in the same realistic turns, the kind of interaction bug per-mechanism unit tests structurally can't catch). One real test bug found and fixed while building the cross-mechanism scenarios (a repair-reachability check that only raised the bond's Affinity side and left Aversion at its post-rupture ceiling, never satisfying `attemptRepair()`'s real A-over-V margin condition) — not a framework bug, but exactly the kind of thing this exercise is for. Corrected `test/property/extreme-personality-and-longrun.test.js`'s C26 assertion direction again — the new mechanics genuinely, deterministically shifted which corner accumulates more cortisol under repeated criticism; verified by hand across 10 identical trials (zero variance) and 3 independent hostile-turn sets before rewriting the test to match the real, current behavior.

Added full-pipeline threshold-crossing checks (real consecutive turns, not isolated module calls), an exhaustive field-by-field `toJSON()`/`restoreState()` round-trip, combined-extreme OCEAN personality corners, `WornPathCache` eviction-boundary checks, malformed/hostile-input robustness, and long-horizon saturation limits.
- Fixed `npm test` accidentally auto-discovering and executing `examples/full-stress-test.js` as a test file.
- Closed the 4 remaining production-scale coverage gaps with 24 real tests in `test/integration/production-gaps.test.js` (2274 → 2298 total): concurrent `processInput()` calls on one instance (no state corruption, finite PAD, coherent per-user memories), memory/window boundedness beyond 500 turns (`MoodTracker.window` capped after 5000 pushes, `EpisodicMemory` pruning verified over 3000 turns via `ForgettingCurve`, an unresolved wound surviving 2000 unrelated turns, PAD staying in bounds over 5000 alternating-valence turns), real provider integration (`OllamaProvider` throwing on an unreachable daemon and `Totemheart` transparently falling back to `HeuristicProvider`, `@xenova/transformers` confirmed importable, the real provider contract exercised with a custom `analyze()`), and non-ES/EN language robustness (French, German, Japanese, Chinese, Arabic, Russian, and mixed-script input all verified to produce a finite, honestly-neutral score — `HeuristicProvider`'s lexicon is ES/EN only, by design, not a bug — with no crash through the full pipeline).
